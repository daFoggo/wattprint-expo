# Vercel RN / React / composition skills audit (2026-10-25)

Note (2026-10-26): the `lab` example feature audited here was removed; file names below are historical.

Scope: `src/features/lab/**`, `src/screens/**`, `src/components/states/**`, `src/app/**`, `src/stores`, `src/lib`, `src/hooks`. Vendored `src/components/ui/**` is report-only. Skills: `vercel-react-native-skills` (all 40 rules), `vercel-react-best-practices` (client/RN rules only), `vercel-composition-patterns`.

## Key evidence: React Compiler decides most list rules

- `app.json` sets `experiments.reactCompiler: true`; `babel-plugin-react-compiler` is installed (babel-preset-expo wires it).
- I ran the compiler standalone over `products-screen.tsx`, `product-row.tsx`, `product-detail-screen.tsx`, `use-nav-theme.ts`, `app/_layout.tsx`, `screens/home/index.tsx`, `sample-form.tsx`, `use-product-search.ts`: every component logged `CompileSuccess`, none bailed out.
- Compiled output of `products-screen.tsx` caches the whole `<FlashList ...>` element keyed on `data, error, isError, onPullToRefresh, paused, pulling, refetch, router, shownQ, t`. The inline `renderItem` and `keyExtractor` (hoisted by the compiler to `_temp3`) therefore keep their identity while typing in the search box (`text` is not a dependency of the list block).
- `useRouter()` (expo-router `useRouterActions`) returns a `useMemo`'d object, so `router` is a stable dependency. The skill's "destructure `push`" advice (`react-compiler-destructure-functions`) is not needed here.
- The skill itself says the same for lists: the `list-performance-callbacks`/`-inline-objects`/`-item-memo` rules note that with the React Compiler enabled, manual memo/`useCallback` is not needed. Adding them would be redundant, so none was added.
